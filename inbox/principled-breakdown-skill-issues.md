# Principled Breakdown Skill 问题清单

审查日期：2026-05-09

审查对象：`skills/principled-breakdown/SKILL.md`、`skills/principled-breakdown/agents/openai.yaml`

## 1. 缺少"不适用场景"

**严重程度**：高

SKILL.md 没有说明什么时候**不应该**触发这个 skill。wiki 写作规范（AGENTS.md）要求每个长期页面包含适用/不适用场景，skill 自身也应遵守此规范。

建议增加：当任务需求已明确、验收标准已定义清楚、任务规模小到不需要正式拆解时，跳过完整流程或只保留简化输出。

## 2. 输出模板缺少规模对照

**严重程度**：高

当前 8 个 section 的模板标注为"默认按以下结构输出"，但没有任务规模与输出粒度的对照指南。小任务（如"加一个按钮"）强行填满 8 段会产生噪音。

建议增加规模对照：
- 小型（单文件/单函数）：只输出意图 + 实施路径 + 验收检查
- 中型（多文件/单模块）：保留意图 + 简化范围 + 实施路径 + 验收检查
- 大型（跨系统/跨仓库）：使用完整 8 段模板

## 3. 苏格拉底提问库存在冗余

**严重程度**：中

10 个问题中有重叠：
- "这个需求解决的真实问题是什么，而不只是表面功能是什么？" 与 "如果不做这个功能，会发生什么？" —— 后者是前者的反面问法，可合并。
- "最小的可观察进展是什么？" 与 "什么情况下它'看起来完成了'，但其实是误导性的？" —— 可以保留两者，但需注意区分。

建议精简到 6-7 个更互斥的问题，或者将问题按阶段分组（澄清阶段 vs 验证阶段）。

## 4. 缺少 walkthrough example

**严重程度**：中

整个 skill 全是规则描述，没有贯穿始终的实例。给一个真实场景（如"用户说：我想做一个自动备份工具"），展示从意图复述 → 提问 → 拆解 → 裁剪 → 输出的完整过程，对 agent 理解 skill 意图远比规则列表有效。

建议在文末或工作流说明后增加一个标注了各步骤对应关系的示例。

## 5. `agents/openai.yaml` 价值存疑

**严重程度**：低

该文件仅包含一个 `default_prompt`，本质上是 SKILL.md 的一句话概括，且只在 OpenAI 环境的 agent 中加载。在当前仓库只面向 Claude Code 的场景下，该文件不起作用。

建议：
- 如果确实需要跨平台支持，应包含完整的 agent 配置（system prompt、tools、parameters），而不只是 default_prompt。
- 如果只面向 Claude Code，可删除此文件，避免维护负担。
